# 実装 → レビュー反復ループ

## 目的

実装フェーズを「実装 → 機械的検証（lint + テスト）→ レビュー（docs → code sequential）→ 指摘分類 → 記録 → 対応」の反復として回し、レビュー指摘 0 件・lint 通過・テスト通過・未決事項なしまで到達させてコミットで閉じる。docs レビューを先行させるのは、code review と次周の fix が信頼できる impl.md をリファレンスに走れる状態を作るため。テスト実行はレビューが拾えない実行時整合を担う唯一のゲートなので、整備されているプロジェクトでは省略しない。

## 参照

- ルール本体は `references/rules.md` を参照する。実装フェーズに入る前に必ず読むこと。
- 役割分担・委譲プロンプト共通要素・エスカレーションプロトコル・モデル選択・コンテキスト管理は subagent-orchestration スキルに従う（git 書き込み操作の扱い含む）。ドキュメントレビューエージェントの役割定義も同スキル参照。
- design.md / impl.md の編集権限・記載範囲は design-impl-docs スキルに従う。
- ドキュメントレビュー実行（step 3a）は subagent-orchestration の「ドキュメントレビューエージェント」役に委譲する。起動契機は design-impl-docs の「中核ルール」節。
- コードレビュー実行（step 3b、3a-fix 完了後）は code-review-agent スキルに従う（5 レンズ並列 + confidence scoring）。
- コミット（最終 step）はコミットエージェントに委譲する。プロジェクトにコミット規約スキル（例: commit-workflow）があれば委譲プロンプトで従わせる。

## 実行手順

1. `references/rules.md` を読む
2. 該当タスクの design.md と impl.md を確認し（impl.md が無ければ design-impl-docs スキルに従って upfront で作成してから先に進む）、実装対象範囲を確定する。反復カウンタ N = 1 で開始
3. 実装エージェントに委譲 → **機械的検証（lint + テスト）**（hook 優先、なければオーケストレーター実行、fail 時は該当修正のみ委譲。テスト未整備でスキップする場合は impl.md に明示記録） → **3a. ドキュメントレビュー**（別エージェント。impl.md の方針セクションを触った周 / design.md 変更後の周のみ実行、実装状況の更新だけなら skip）→ 3a 指摘の即対応（impl.md 修正 or エスカレーション halt） → **3b. コードレビュー**（reconciled 済み impl.md をリファレンス）→ 3b 指摘を「仕様・設計」と「実装判断」に分類する
4. 仕様・設計は design.md 経由でユーザーへエスカレーション、それ以外は impl.md の「レビュー指摘と対応」に周ごとに記録して対応を決める
5. コード修正対応を実装エージェントに委譲して N++ で 3 に戻る。「docs + code レビューとも指摘 0 件 + lint 通過 + テスト通過（or 明示 skip 記録済み）+ 未決事項なし」を確認したらコミットエージェントに委譲してコミット完了を確認し、完了報告して終了（UI・外部影響・仕様確認要・テスト skip したケースのみ動作確認依頼を添える）。N == 3 で終了条件未達なら design.md 未決事項に状況・選択肢・推奨を記録してユーザーへエスカレーション
